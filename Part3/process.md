## AI prompts used

These are the prompts that were used to build the two new features.

### Plan Finder quiz (new feature)

> Build a "Plan Finder" quiz as the new feature on the Pricing page. It should sit above the three pricing cards and ask three short questions, one at a time: who will be breathing (just me / family / whole company), how seriously the visitor takes their air, and what level of support they expect. Each answer adds weighted points to each of the three plans (Casual Breather, Power Inhaler, Enterprise Lung), and when the last question is answered, the plan with the highest total wins. On completion: show a result card naming the recommended plan with its tagline and price, smooth-scroll the page to the matching pricing card, and highlight that card with a violet "Recommended for you" badge and ring that takes priority over the default "Most Popular" styling. Persist the recommendation in localStorage so a returning visitor still sees their plan highlighted, validate the stored value against the known plan list before using it, and include a "Retake the quiz" link that clears the stored result and restarts from question one. Animate the transition between questions with Motion's AnimatePresence and show an animated progress bar. Keep the quiz state (question index, running scores) inside the quiz component, but lift the recommendation state up to the parent pricing section so both the quiz result view and the plan cards can read it.

### Dark/light mode with persistent preference

> Add a dark/light mode to the whole site with a persistent user preference. Requirements: a toggle button in the header (visible on both desktop and mobile) that switches the theme and saves the choice to localStorage; first-time visitors with no saved choice should get their operating system preference via prefers-color-scheme; and the saved theme must be applied before first paint so there is no light-mode flash when reloading in dark mode — inject a small inline script into the document head with next/script and strategy="beforeInteractive" that reads localStorage and sets a `dark` class on the html element. Use Tailwind CSS v4's class-based dark mode (@custom-variant dark) rather than the default media-query strategy, then go through every component — hero gradients, cards, borders, form inputs, timeline connectors, text colors — and add tuned dark: variants; sections that are already dark (testimonials, footer, newsletter box) should get subtle borders so they stay visually distinct against the dark page background. Avoid hydration mismatches: the toggle icon (moon/sun) must be chosen by CSS with dark:hidden / dark:inline classes instead of React state, so the server and client render identical markup, and put suppressHydrationWarning on the html element since the inline script changes its class before hydration.
